v9 Lean Results

The v9 programme looked for accuracy gains that cost no latency, using only the challenge's safe-list operators. The best candidate, k8_combined, cuts validation error by 0.080° against our current best and runs 39% faster on the CPU latency proxy. The model choice and five other decisions are for the team, listed at the end.

Two candidates, one recipe

Both candidates keep what the current model already has: separable blocks, mirror and gravity features, the damped-velocity prior and the angular loss. Both add the same three training changes from the screen: window sampling, native maps and 15° tilt augmentation. They differ in the network. k8_combined has 3 blocks with kernel 8 and 32 channels per mirror stream. k5_combined has 4 blocks with kernel 5 and 24 channels per stream. Each sees 393 to 397 samples of history, where the current model sees 243.

Where the gain came from

Each change was first screened alone on seed 42 and compared per user with the same control (4.3386°). Changes that passed the agreed rule were combined and confirmed on three seeds. For k8 the gains added up almost exactly: 0.092° on seed 42, against 0.094° summed from the screen. For k5 they added up to less, 0.073° against 0.095°.

Timing jitter is the open risk

The organisers say the test stream is about 100 Hz with some jitter. We resampled validation at jittered times and fed the samples as if evenly spaced, as the harness will. Every model trained on our exact grid loses about 0.05° at ±1 ms and 0.16° at ±2 ms. Most of that comes from the network, which leans on step-to-step differences that are clean on an exact grid. The damped baseline uses the same last-step velocity and barely moves.

Training the k8 screen model with ±3 ms jitter almost removes the loss, but costs 0.030° on the exact grid. That failed the agreed rule (at most +0.01°), so jitter stayed out of the final candidates. Against k8_combined, the jitter-trained screen model only wins above about ±1.4 ms. A k8_combined trained with jitter would probably break even near ±0.8 ms. That figure is an estimate from the screen pair, not a measurement.

Frame conventions

The organisers will convert the test data to the frame we document. These rows show what a conversion mistake would cost. Heading changes and left-right mirroring cost nothing, by design. Tilt augmentation halved the cost of a 15° world tilt. A wrong up axis or handedness still costs 0.1° to 1.9°, so the written frame spec matters more here than any model change.

Decisions for the team

Nothing below has been decided. Recommendations were AI-generated and are labelled as such.

D1

Which model to submit

k8_combined

4.2501° (−0.080). 55.2 µs lean. 7,555 parameters, 16.2K MACs, 25,088 state floats (98 KB in fp32).

k5_combined

4.2717° (−0.058). 61.9 µs lean. 5,595 parameters, 12.3K MACs, 19,008 state floats (74 KB).

k8_combined is 0.022° more accurate and 6.7 µs faster. It is also 35% larger in parameters and 32% larger in MACs. The challenge has not said how size is scored.

Recommendationk8_combined, unless the team expects the size score to weigh parameters heavily.

D2

Which graph form

Lean

60 nodes, 55.2 µs. Every weight is stored as it is used. The safest choice for an unknown runtime.

Padded rows

54 nodes after load-time folding (57 in the file), 48.3 µs (−13%). 38% more MACs. Tied weights are stored once and rebuilt by Concat nodes that ONNX Runtime folds at load.

Padded rows + fused head (A4)

51 nodes after folding (58 in the file), 46.9 µs (−15%). Stored weights equal the declared 7,555.

If ST's deployment tool does not fold constants at load, the padded graphs run their extra nodes on every call and may lose their lead.

RecommendationLean, unless the organisers confirm that constants are folded. Keep padded as a measured option.

D3

Whether to train for timing jitter

Ship as trained

Best if the test stream jitters by less than about ±1 ms.

Add k8_combined + jitter 3 ms

3 seeds, about 2.4 GPU hours. Expect about +0.03° on an exact grid, with most of the jitter loss removed.

Screen a gentler setting first

For example 1.5 ms on seed 42, about 50 minutes, to look for a cheaper point on the trade-off.

Ask the organisers

How large the jitter is, and whether it is in the samples or only in the timestamps. The text is in D4.

RecommendationAsk now, and train k8_combined + jitter 3 ms while waiting, so a hedge model is ready whichever way they answer. The GPU is free.

D4

Question for the organisers

For Jacob to send, to both addresses in the FAQ.

Thank you for confirming that the test stream has some timing jitter. It affects which model we submit, so could you tell us a little more? 1. Is the jitter in the sampling times (each quaternion is the true pose at an irregular instant), or only in the timestamps (the samples come from a fixed-rate sensor and are evenly spaced)? 2. Roughly how large is it? For example, the standard deviation or the largest deviation of the interval between samples, in milliseconds. 3. Are samples ever dropped or repeated? D5

Score the test set once

Not run. The plan scores the test set once, for reporting, after D1 to D3 are settled. Scoring only the chosen model keeps the test set from steering the choice.

D6

Model card items

  • Frame: an exact spec with worked examples, checked against the ray pipeline first. A wrong up axis costs 0.8° to 1.0°, and flipped handedness costs 0.13°.
  • Stateful use: feed the full [1, 400, 4] window on every call, newest sample last. Zero the three state tensors at session start. Start scoring after 400 calls; the receptive field is 393 for k8 and 397 for k5.
  • Output: prediction is [1, 20, 4], unit quaternions normalised in the graph.
  • Parameters: 7,555 declared. The ONNX file stores 7,552 floats because three head biases sit in a Constant node; with A4 it stores all 7,555.
  • Operators in the k8 lean graph (60 nodes): MatMul 11, Slice 11, Concat 9, Relu 8, Conv 7, Reshape 7, Add 3, Mul 3, LayerNormalization 1. No Clip. List Add and Mul as the elementwise operators the organisers asked about.
  • Jitter: whatever D3 decides, state that training used an evenly spaced 100 Hz grid.

How this was measured

  • Accuracy: mean geodesic error at step 20 (200 ms) over all 657,189 validation windows from 15 users, on seeds 42, 43 and 44. Each candidate is compared per user with the reference, with a window-weighted bootstrap over users for the 95% CI.
  • Reference: today's best, sep_base3_addons with angular loss, in outputs/v8_recipe_sep_base3_addons/angular_loss.
  • Latency: ONNX Runtime on CPU, one thread, median over 5 alternating rounds of 3,000 calls, on jacob-amd at 07:57 on 29 Oct. The machine may not have been fully idle; the numbers agree with earlier sessions to within 4%.
  • Robustness: validation at stride 5 (131,459 windows) with seed-42 checkpoints and a single jitter draw.
  • Test set: not used.
  • Code: jacob/training/experimental/v9_lean/, uncommitted. It imports experimental/v7_compact/, which is also uncommitted. The final plan is experimental/v9_lean/configs/v9_confirm.json; runs are in outputs/v9_screen, v9_distill, v9_jitter and v9_confirm.
